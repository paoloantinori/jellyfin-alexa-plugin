## Why

The full live NLU suite takes about two hours (about 1450 rows across 17 locales, with a 1.5 second SMAPI delay per row). On 2026-11-23 it was the only verification available after a change that touched two locales, and a long run increases the chance that a catalog sync or rebuild happens in the middle. Two deterministic facts can shrink it: which locales' models actually changed, and which intents inside them changed plus their competitors. This task computes both and lets the suite run only the affected rows. The full suite remains the release gate; this is the fast inner loop. Read parent JF-954 first; its "Rules that apply to EVERY subtask" section is binding. Depends on JF-954.1 (`build_effective_model`, `normalize_text`, CLI skeleton) and JF-954.4 (the subsumption graph builder in `scripts/nlu_static/graph.py`, used for the neighbour relation).

## Part A: model identity

`python3 scripts/nlu_static/cli.py identity [--locale X|--all] [--snapshot f.json] [--format json|text]` prints, per locale, `committed_sha256` (sha256 of the canonical JSON of the committed `languageModel`: keys sorted, compact separators, UTF-8, no ASCII escaping) and, when a snapshot is given, `effective_sha256` computed the same way over the effective model (types replaced by snapshot entries, entries sorted). Canonical JSON means two models that differ only in key order or whitespace have the same hash; a changed sample, slot, type value or synonym changes it. Sample ORDER inside an intent is kept as is (order is part of the generated model and a reorder must show up).

## Part B: selection

`python3 scripts/nlu_static/cli.py select --base <git-ref> [--locale X|--all] [--no-neighbours] [--out rows.json]`.

For each locale compare the model at `<git-ref>` (read with `git show <ref>:<path>`; a locale whose file does not exist at the base counts as fully changed) with the working tree:
1. If the canonical hashes are equal, the locale is UNCHANGED and contributes no rows.
2. Otherwise compute the CHANGED INTENTS: intents added or removed, intents whose `slots` or `samples` differ, and every intent that declares a slot whose TYPE changed (values or synonyms differ, type added or removed). If `invocationName` differs, every intent of the locale is changed.
3. Unless `--no-neighbours`, add the NEIGHBOURS: every intent connected by an edge (either direction) to a changed intent in the subsumption graph of the OLD model or of the NEW model. For ja-JP, where no graph exists, a changed locale selects all of its intents and the output says so.
4. Select every fixture row of that locale (from `tests/integration/fixtures/<locale>.yaml`, never `e2e_*.yaml`) whose `expected_intent` alternatives intersect the selected intent set.

Output JSON (sorted): `{"schema": 1, "base": "<ref as given>", "locales": {"es-ES": {"status": "changed", "changed_intents": [...], "neighbour_intents": [...], "rows": ["utterance one", ...]}, "fr-FR": {"status": "unchanged"}}, "totals": {"rows_selected": N, "rows_total": M}}`. Text mode prints one summary line per locale and the totals.

Safety rule: selection must never silently drop coverage. When anything prevents a precise answer for a locale (model unreadable at base, graph build error), that locale falls back to ALL of its rows and the output records `"status": "fallback_all"` with the reason.

## Part C: honouring the selection in the live suite

`tests/integration/conftest.py` already has a `pytest_collection_modifyitems` hook. Add: when the environment variable `NLU_ROW_FILTER` points to a rows file produced by `select`, NLU test items whose `(locale, utterance)` is not listed are deselected (use pytest's deselection so the summary shows the count), and one line is printed stating how many rows were kept and from which file. When the variable is unset, behaviour is byte-for-byte what it is today. A filter file that cannot be read or has the wrong schema ABORTS the session with a clear error; it must not fall back to running nothing or everything silently. The matching compares utterances after `normalize_text`. Non-NLU tests (E2E and others) are never touched by the filter. Put the pure decision function (`should_keep(locale, utterance, selection) -> bool` and the file loader) in `scripts/nlu_static/selection.py` so it is unit-tested in `tests/scripts/`; the conftest hook only calls it.

## Guidance

- Reuse the graph builder; do not reimplement matching. Build the old model's graph from the JSON obtained via `git show` by passing the parsed dict to the builder (if the builder only accepts a locale name, add an overload that accepts a model dict; do not write temp files into the repo).
- Tests in `tests/scripts/test_nlu_static_selection.py` with synthetic old and new models as dicts: unchanged model selects nothing; a changed sample selects that intent's rows; a changed type value selects every intent using the type; a neighbour is added through an old-graph edge and through a new-graph edge; `--no-neighbours` removes them; invocation name change selects everything; fallback_all on an unreadable base; `A|B` expected intents select the row when either is in the set.
- Extend `docs/nlu-static-analysis.md`: the fast-loop recipe (`select --base main --out rows.json`, then `NLU_ROW_FILTER=rows.json ./scripts/run_nlu_tests.sh`), and the explicit statement that the full suite is still required before a release because the trainer can move rows the static analysis does not connect (cite the es-US ablation of 2026-11-23, where untouched carriers moved).

## Out of scope

Catalog-driven selection (a catalog change with unchanged models), the E2E suite, any SMAPI call, changing fixtures or models.
