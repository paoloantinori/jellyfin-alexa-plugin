## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Why

On 2026-11-23 the live NLU suite reported the es/fr episode rows red (for example es-ES "reproduce breaking bad temporada uno episodio tres", expected PlayEpisodeIntent with `series_name` = "breaking bad"). The same rows were green on the lab skill. Cause, found by reading code after the fact: the `series_name` slot uses the catalog-backed custom type SeriesName. The committed model's static seed contains "Breaking Bad", so the lab matches. On the live skill, catalog sync REPLACES the seed with the user's library series (Series seeds are deliberately not merged into the catalog payload, see `CatalogSeedEnrichment.GetSeedNames` in `Jellyfin.Plugin.AlexaSkill/Alexa/Catalog/`), and the maintainer's library has no "Breaking Bad". A value that matches nothing in a catalog-backed type discourages selection of that intent (project finding JF-684), so an already marginal phrasing fell to another intent. A two-hour suite was needed to see something a dictionary lookup shows in milliseconds.

This task adds that lookup. Read parent JF-954 first; its "Rules that apply to EVERY subtask" section is binding. Depends on JF-954.1 (`build_effective_model`, `load_snapshot`, `classify_slot_type`, `normalize_text`, `tokenize`, CLI skeleton in `scripts/nlu_static/`).

## Behaviour

For each locale, read `tests/integration/fixtures/<locale>.yaml` (skip `e2e_*.yaml`). For each test row, for each intent name in `expected_intent` split on `|`, for each slot name in `expected_slots`:

1. Resolve the slot's type from that intent's `slots` in the effective model. If the intent does not exist in the locale model, or does not declare that slot, record status `FIXTURE_SLOT_UNKNOWN` (a fixture authoring bug). If at least one alternative intent declares the slot, do not report the alternatives that lack it.
2. If the type class is not CLOSED (free-text or built-in), record `NOT_APPLICABLE` and stop for this slot.
3. If the expectation pins a value (`{value: "x"}`): status `PRESENT` when `normalize_text(x)` equals the normalized canonical value or any synonym of the effective type, otherwise `ABSENT`.
4. If the expectation is `{}` (any non-empty value): status `PRESENT` when at least one entry of the effective type occurs as a contiguous token sequence in the utterance, otherwise `NO_ENTRY_IN_UTTERANCE` (the row relies on the trainer generalizing beyond the vocabulary). For ja-JP use substring containment on `normalize_text` output instead of token sequences, since there are no word spaces.

Each result also carries `type_kind` (`STATIC` or `CATALOG`) and `mode` (`committed` or `snapshot`).

## Two entry points

- Validator: a warning phase in `scripts/validate_interaction_models.py` titled "Phase 12: fixture slot values versus slot type vocabulary (JF-954 warning check)", committed mode only, reporting `ABSENT`, `NO_ENTRY_IN_UTTERANCE` and `FIXTURE_SLOT_UNKNOWN` rows. This mechanizes anti-pattern #8 in the project CLAUDE.md ("Missing Slot Type Values for Test Fixtures"). If the fixtures directory is missing, print a SKIP line and return `None`.
- CLI: `python3 scripts/nlu_static/cli.py fixtures [--locale X] [--snapshot f.json] [--format json|text]`. With a snapshot it answers the live question: which fixture rows pin a value that the live catalog does not contain. JSON output is a sorted list of objects with `locale`, `utterance`, `expected_intent`, `slot`, `type`, `type_kind`, `status`, `mode`. The JSON form is consumed later by the triage subtask, so keep the field names exactly as written here.

## Handling findings on the committed fixtures

Run the validator on the committed tree. If the new phase reports findings, do NOT edit fixtures or templates to silence them. List every finding in the task notes, grouped by locale and status, so the maintainer decides per case (some rows deliberately test unknown values such as "xyzzyfoo"). If the count is large enough to drown the validator output (more than 30), add the same committed-baseline mechanism used by the token lint subtask (a sorted JSON list of finding identities, warn only on new ones) in `scripts/nlu_static/fixture_vocab_baseline.json`, and say so in the notes.

## Guidance

- The matching of `{}` rows must use the shared `tokenize`; do not lowercase by hand.
- Keep the checker a pure function `check_fixture_rows(effective_model, fixture_rows) -> list[Result]`; the validator phase and the CLI are thin wrappers. The triage subtask imports this function.
- Tests in `tests/scripts/test_nlu_static_fixture_vocab.py` with synthetic models and fixture dicts. Required real-data test: with the committed es-ES model and the committed es-ES fixture file, the row "reproduce breaking bad temporada uno episodio tres" is `PRESENT` in committed mode, and becomes `ABSENT` with `type_kind` CATALOG when given a snapshot whose SeriesName list is `["Adolescencia"]`.
- Extend `docs/nlu-static-analysis.md`: what the check means, the lab-green/live-red story as worked example, and the practical rule for fixture authors (a live fixture that pins a value on a catalog-backed slot should use an item that exists in the test library, or the row should be marked as catalog-dependent in its comment).

## Out of scope

Changing fixtures, templates, models or the C# seed-merge behaviour. Any SMAPI call.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Read the STATE CHANGE note on the parent JF-954 first. Two refinements follow from it and are now part of the acceptance criteria. (1) Fixture rows are being moved to series that exist in the test library and are absent from the committed seed (for example "adolescencia"). Such rows are legitimately ABSENT in committed mode on a CATALOG type, so the validator must not print one warning per row for them; it prints a single count line, and the full list stays available through the CLI (`fixtures --format json`). (2) The name-level snapshot producer (`producer: jellyfin-names`) lists library names only, while the plugin merges model seeds into the real payload for some types (Album, Artist, Audiobook, Movie, and Series once the pending change lands). A value that is missing from a name-level snapshot but present in the committed seed is therefore probably present live. Report it as `ABSENT_IN_LIBRARY_SEED_ONLY`, never as plain `ABSENT`. Do not re-implement the plugin's seed-merge rules in Python; this two-status approach is the deliberate alternative. With the authoritative snapshot (`producer: plugin`, subtask JF-954.8) the payload already contains whatever seeds the plugin merges, so plain `ABSENT` is correct there. The JSON `status` field gains this one extra value; the triage subtask treats it as a signal, not as a FIXTURE_VOCAB verdict.

The description's required real-data test that reads the row from the committed es-ES fixture file is SUPERSEDED by the new acceptance criterion: build the rows inline.
