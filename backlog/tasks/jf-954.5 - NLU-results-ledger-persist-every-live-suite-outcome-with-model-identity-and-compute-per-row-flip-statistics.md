## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Why

The live NLU suite (`./scripts/run_nlu_tests.sh`, which runs `tests/integration/test_nlu.py` through pytest, about 1450 rows and two hours for all locales) prints pass or fail and then forgets everything. When 45 rows went red on 2026-11-23, the central question was "did these rows ever flip before without a template change?" and nobody could answer, because no history exists. Amazon retrains the model on every build and some rows change intent between builds of identical content (tracked for two it-IT rows in JF-945). A row that has flipped before under an unchanged model is noise; a row that was stable for ten builds and is now red is a signal. Today that distinction is a human guess. This task records the data that turns it into a lookup. Read parent JF-954 first; its "Rules that apply to EVERY subtask" section is binding. Depends on JF-954.1 only for `normalize_text` and the CLI skeleton in `scripts/nlu_static/`.

## Part A: the ledger writer

Module `scripts/nlu_static/ledger.py` (pure Python, unit-testable without pytest fixtures). One JSON Lines file per suite session in `tests/integration/results/` named `nlu-<UTC yyyymmddThhmmssZ>-<pid>.jsonl`. Add that directory to `.gitignore`. Record types, one JSON object per line:

- `session_start`: `schema` (1), `session_id` (the file stem), `started` (UTC ISO 8601), `skill_id`, `git_head`, `git_dirty` (bool), `locales` (object, filled lazily, see below).
- `locale_start`, written the first time a locale is exercised: `locale`, `model_sha256` (sha256 of the bytes of the committed `model_<locale>.json`), `live_identity_start` (string or null).
- `row`: `locale`, `utterance` (verbatim), `expected_intent` (verbatim, may contain `|`), `actual_intent` (string or null), `slots` (object slot name to resolved value string), `outcome` (`pass`, `fail`, `error`), `failure_kind` (null, `intent`, `slot_missing`, `slot_empty`, `slot_value`, `smapi_error`), `detail` (short string or null).
- `session_end`: `ended`, `rows`, and per exercised locale `live_identity_end`.

Rules:
- Each line is written and flushed immediately, so an interrupted run keeps its rows. A file without `session_end` is an INCOMPLETE session; statistics still use its rows and mark the session incomplete.
- `live_identity` is the identity of the model build currently live on the skill for that locale, so the ledger can prove whether a rebuild happened DURING the run. Read `scripts/nlu-lab/smapi_ops.py` to see how the lab reads the interaction model eTag from SMAPI and use the same read-only call through the existing `tests/integration/smapi_client.py` wrapper (add one small read-only method there if none exists). If the identity cannot be obtained for any reason, record null and continue. Obtaining it costs at most two SMAPI read calls per locale per session.
- The ledger must NEVER change a test outcome. Any exception inside ledger code is caught, reported once as a pytest warning, and the suite continues without a ledger.
- Dry-run mode (`--dry-run`) writes nothing. The environment variable `NLU_LEDGER=0` disables the ledger; any other value or unset leaves it enabled for live runs. `NLU_LEDGER_DIR` overrides the directory.

## Part B: wiring into the suite

In `tests/integration/test_nlu.py` and `tests/integration/conftest.py`: create the writer once per pytest session, record one `row` per executed test with the outcome as the test decided it, and close the session at the end. Read `test_nlu.py` first: the intent assertion and the three slot assertions already distinguish the failure kinds listed above; map each to its `failure_kind` without changing the assertion messages or the pass/fail behaviour. Import the writer from `scripts/nlu_static` by adding the repo's `scripts` directory to `sys.path` in `conftest.py`. Skipped rows are not recorded.

## Part C: statistics

`python3 scripts/nlu_static/cli.py ledger stats [--dir D] [--locale X] [--last N] [--format json|text]`. Sessions are ordered by `started`, ties broken by `session_id`. The row key is `(locale, normalize_text(utterance))`. For each key output: `runs`, `passes`, `fails`, `errors`, `actual_intents` (sorted distinct values), `flips_total` (number of adjacent session pairs where `actual_intent` differs, ignoring sessions where the outcome is `error`), `flips_same_model` (same count restricted to adjacent pairs whose `model_sha256` for that locale is equal: these are flips with no template change), `last_outcome`, `last_actual_intent`, `first_session`, `last_session`. Also output per session: `complete` (bool) and, per locale, `rebuilt_during_run` (true when both identities are non-null and differ, null when either is null).

`ledger list` prints the sessions with row counts, completeness and the rebuilt flags.

Statistics output is deterministic for a given set of ledger files: sorted keys, sorted rows, no "now" timestamps.

## Guidance

- The writer takes its clock, its git reader and its identity reader as injectable callables so unit tests need no git, no time and no network.
- Tests in `tests/scripts/test_nlu_static_ledger.py`: build small ledger files in `tmp_path` and assert the statistics. Cover: a stable row, a row that flips with the same model sha, a row that changes only when the model sha changes (must count in `flips_total` but not in `flips_same_model`), an error row between two passes (not a flip), an incomplete session, a session with a rebuild during the run.
- Do not import the lab's run files (`scripts/nlu-lab/runs/`) into the ledger; they come from a different skill without catalogs and would pollute flip rates.
- Extend `docs/nlu-static-analysis.md` with the ledger location, the record format, the meaning of the two flip counters, and the reading rule: a red row with `flips_same_model` of zero over many runs deserves investigation, a red row with a history of same-model flips is trainer noise and should be annotated in its fixture comment.
