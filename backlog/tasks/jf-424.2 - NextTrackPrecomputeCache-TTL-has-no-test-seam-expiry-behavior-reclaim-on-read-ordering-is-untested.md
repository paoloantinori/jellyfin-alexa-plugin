## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Surfaced by the JF-424 review (confirmed finding). NextTrackPrecomputeCache.EntryTtl is a private static hardwired 15 minutes compared against DateTimeOffset.UtcNow, with no seam, and NO test anywhere exercises expiry behavior: every cache test in PreEnqueueOnStartTests completes in milliseconds against a 15-minute window (even the test named MissesEvenWithinTtl documents the assumption without verifying it). A future refactor that reorders the expiry and token checks, or drops the remove-on-expired, would pass the entire suite.

Context for the expected behavior (current shape after JF-424): the TTL check runs BEFORE the token check, so an expired entry is reclaimed on any read (matched or not); a fresh entry survives a mismatched read (the JF-424 fix) and is consumed only on a matching read. The class is static, so SearchResultCache's constructor-parameter pattern does not transfer directly; candidates are an injectable TimeProvider or an internal-for-test TTL override.
