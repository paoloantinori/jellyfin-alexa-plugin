## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Three smaller findings from the JF-513 code review, all outside that task's two-file scope, none behavior-breaking today:

1. Fragile skill-name lookup (Jellyfin.Plugin.AlexaSkill/Alexa/SmapiManagement.cs:339): FindExistingSkillAsync derives expectedName from `PublishingInformation?.Locales?.Values.FirstOrDefault()?.Name`, which is JSON insertion-order dependent. JF-513 inserts ar-SA first, so the first locale changed from de-DE to ar-SA; the lookup only stays correct because all 17 Name values are the literal 'Jellyfin' (JF-513 deliberately pins that). If someone later localizes the ar-SA block's name to an Arabic display name, expectedName matches nothing in the cloud listing's nameByLocale and the plugin creates a DUPLICATE skill instead of reusing the existing one (the skill-ID churn class this lookup exists to prevent). Fix: pin the name to a stable locale (e.g. en-US) or match against any locale's Name.

2. Catalog-sync volume growth (Jellyfin.Plugin.AlexaSkill/Alexa/Catalog/LibrarySyncService.cs:411): with CatalogSyncLocales at its code default '*', the weekly sync's active-locale set grows 12 -> 17 once the 17-locale manifest is live (+5 locales x 3 catalog types = +15 serialized SMAPI catalog-version uploads with fetch/poll/retry; the payload cache transiently holds up to 51 blobs). ar-SA and hi-IN have no PhoneticSynonymGenerator (empty-list default), so their uploads are near-duplicate payloads adding no phonetic value. Cheaper: hash the serialized payload and skip re-minting identical catalog versions; per-locale failures are warnings only, so tail locales can silently lose coverage when a longer run hits throttling.

3. Manifest resource-path literal: 'Jellyfin.Plugin.AlexaSkill.Alexa.Manifest.manifest.json' is hardcoded at 5 sites (3 tests in Jellyfin.Plugin.AlexaSkill.Tests/Alexa/Manifest/ManifestSkillTests.cs + PluginConfiguration.cs:515 + SkillStartup.cs:104) with no shared constant. Hoist a single const (natural home: ManifestSkill) and reference it from all sites so a resource rename is one edit.
