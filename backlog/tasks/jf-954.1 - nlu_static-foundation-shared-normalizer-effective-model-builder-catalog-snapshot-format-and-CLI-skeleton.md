## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Why

Every other subtask of JF-954 needs the same three things: one text normalizer, one way to load a locale's model as the vocabulary Amazon will actually train on, and one CLI entry point. Building them once prevents four slightly different tokenizers and loaders. Read the parent task JF-954 first; its section "Rules that apply to EVERY subtask" is binding here.

The key concept is the EFFECTIVE MODEL. The committed `model_<locale>.json` carries a small static seed for each catalog-backed slot type (for example SeriesName has 10 seed titles). On a user's live skill, catalog sync replaces that seed with the user's library values. A check that reads only the committed model sees a vocabulary that does not exist on the live skill. The effective model is the committed model with the values of catalog-backed types replaced by a catalog snapshot.

## Deliverables

1. Package `scripts/nlu_static/` (underscore, so it is importable; note the existing `scripts/nlu-lab/` has a hyphen and needs a path bootstrap, do not copy that pattern) with `__init__.py`.

2. `normalize.py` with exactly two public functions:
   - `normalize_text(s) -> str`: Unicode NFC, `casefold()`, every run of whitespace collapsed to one ASCII space, stripped.
   - `tokenize(s) -> list[str]`: `normalize_text`, split on spaces, strip leading and trailing punctuation from each token (use `unicodedata.category(ch).startswith("P")`), drop empty tokens. Inner apostrophes and hyphens stay ("l'album" is one token, "schlaf-timer" is one token).
   - `is_whitespace_tokenized(locale) -> bool`: False for ja-JP (Japanese samples have no word spaces), True for the other 16. Tools that depend on word tokens must print `SKIP ja-JP: no whitespace tokenization` instead of producing output for it.

3. `effective_model.py`:
   - `load_locale_model(locale, models_dir=None) -> dict` returning the `languageModel` dict; accept both a bare file and one wrapped in `interactionModel`.
   - Dataclasses (frozen) `SlotTypeVocab(name, kind, entries)` where each entry is `(canonical, tuple_of_synonyms)` and `kind` is one of `STATIC`, `CATALOG`; and `EffectiveModel(locale, intents, types, source)` where `source` is `"committed"` or `"snapshot"`.
   - `CATALOG_TYPE_NAMES = ("AlbumName", "AudiobookTitle", "JellyfinArtist", "MovieTitle", "SeriesName", "SongTitle")` with a comment pointing at `Alexa/Catalog/CatalogSlotTypes.cs` as the source of truth, plus a unit test that greps that C# file and fails if the name sets diverge.
   - `build_effective_model(locale, snapshot=None)`: with no snapshot every type keeps its committed values (kind STATIC, or CATALOG for names in `CATALOG_TYPE_NAMES`, still with seed values). With a snapshot, each type named in the snapshot for that locale has its entries REPLACED by the snapshot entries; types absent from the snapshot keep committed values. A snapshot type that the locale model does not declare is ignored and listed in `EffectiveModel.notes`.
   - `classify_slot_type(type_name, effective_model) -> str` returning one of `FREE`, `NUMERIC`, `STRUCTURED`, `CLOSED`, `UNKNOWN_BUILTIN`. Pinned table: FREE = AMAZON.SearchQuery, AMAZON.MusicRecording, AMAZON.Musician, AMAZON.Genre, AMAZON.Person; NUMERIC = AMAZON.NUMBER; STRUCTURED = AMAZON.DURATION, AMAZON.TIME; CLOSED = every custom type (STATIC or CATALOG). Any other `AMAZON.*` name returns `UNKNOWN_BUILTIN`; callers treat it as FREE and report it, so the table gets maintained instead of silently guessing.

4. Catalog snapshot format, documented in the doc page and validated by `load_snapshot(path)`:
```json
{
  "schema": 1,
  "producer": "jellyfin-names" ,
  "locales": {
    "es-ES": { "SeriesName": [ {"value": "Adolescencia", "synonyms": []} ] }
  }
}
```
   A special locale key `"*"` applies to every locale that has no entry of its own. `load_snapshot` rejects unknown schema numbers, non-list type entries and entries without a string `value`, with a clear `ValueError` message naming the offending path. Values are stored as given; normalization happens at comparison time.

5. Snapshot producer `producer_jellyfin.py` plus CLI subcommand `snapshot`: reads item NAMES from a Jellyfin server and writes a snapshot with `producer: "jellyfin-names"` under the `"*"` locale. Mapping: Series to SeriesName, MusicArtist to JellyfinArtist, MusicAlbum to AlbumName, Movie to MovieTitle, AudioBook to AudiobookTitle, Audio to SongTitle. Connection from `--url`/`--api-key` or env `JELLYFIN_URL` and `JELLYFIN_API_KEY`. Authentication MUST use the query parameter `ApiKey=<key>` (capital A and K); Jellyfin 12 rejects `X-Emby-Token` and lowercase `api_key` with 401. Use `GET /Items?IncludeItemTypes=<Type>&Recursive=true&Fields=` (artists: `GET /Artists`). Names are de-duplicated case-insensitively and sorted. This producer is NAME-LEVEL: it does not reproduce the plugin's phonetic synonyms, the 140-character truncation or the 50000-value cap, and the doc page must say so. The authoritative producer is a separate subtask of JF-954 (the plugin export); the format is the contract between them. The HTTP call sits behind one small function so tests replace it with a fake; never print or write the API key.

6. `cli.py` with `argparse` subcommands, runnable as `python3 scripts/nlu_static/cli.py <subcommand>`. This task ships `snapshot` and `effective` (`effective --locale es-ES [--snapshot f.json]` prints a deterministic JSON summary: per slot type its kind, entry count and source). Later subtasks add their own subcommands to this same file; keep registration one function per subcommand so additions do not conflict.

7. `docs/nlu-static-analysis.md`: purpose, the effective-model concept in plain words, the snapshot format, the name-level caveat, one runnable example per subcommand.

## Guidance

- Keep modules small and pure: loaders return data, the CLI does the printing. Later subtasks import these functions.
- Do not import from `scripts/validate_interaction_models.py` (it is a 1600-line script with side effects at import in places); reading the model JSON directly is a few lines.
- Tests go in `tests/scripts/test_nlu_static_foundation.py`. Build tiny models as Python dicts written to `tmp_path`; one test may additionally load the real committed es-ES model to prove the loader works on real data (assert SeriesName is CATALOG and contains "Breaking Bad" in committed mode).
- Do not add `scripts/nlu_static` output files to git; write outputs only where the user points with `--out`, default stdout.

## Out of scope

Any lint or analysis (other subtasks). Any SMAPI call. Any change to models, templates, fixtures or C# code.
