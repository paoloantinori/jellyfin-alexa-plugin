## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
New code-review finding (2026-08-31 second high pass, PLAUSIBLE with constructible scenario; verifier confirmed code shape). PlayArtistSongsIntentHandler.cs:441 (the JF-420 margin comparison). Distinct from jf-420.1 (equality bypass does not fix this).

DEFECT: the gate compares the containment match's PENALIZED fair score (ContainmentScore * name/query length ratio) against the alternative's RAW score, with no symmetric penalization and no full-coverage check on the alternative. So a containment-exemption 90 on the ALTERNATIVE side can auto-select the worse artist.

SCENARIO: query 'miles davis live' with 'Miles Davis' and 'Miles' in the library. Tier-2 prefix ties both at 90 (pool row order decides; ArtistIndexService sets no OrderBy). If 'Miles Davis' wins tier 2, the gate's FindBestMatchWithScore gives 'Miles' 90 via the same containment exemption (ApplyLengthPenalty exempts contained candidates), and 90 - 90*11/16 (=61.9) = 28.1 > ContainmentVsFullNameMargin(20) auto-selects 'Miles', discarding the better 'Miles Davis' match the user asked for.

FIX SHAPE: make the comparison symmetric (penalize the alternative's containment-shaped score identically, or drop the exemption for the margin computation) AND require the alternative to cover the full query before it can win by auto-select. Coordinate with jf-420.1 (same code region; land order matters for the tests).
