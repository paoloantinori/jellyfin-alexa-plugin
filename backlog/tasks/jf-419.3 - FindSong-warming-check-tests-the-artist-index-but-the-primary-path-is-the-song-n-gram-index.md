## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Code-review finding (2026-08-31, high effort) on the JF-419 implementation. FindSongIntentHandler.cs:155.

DEFECT: FindSong's warming check tests the ARTIST index, but FindSong's primary path is the song n-gram index (SongNgramIndexService) whose independent IsReady is never checked. After a restart the artist index can be ready in ~2s while the song index (all Audio items) is still building: the gate passes, stages 1-2 are skipped by the inline `_songNgramIndex is { IsReady: true }` checks (lines 499/513), the request falls to the stage-3 Jellyfin search API, and the response can exceed Alexa's ~8s window. INVALID_RESPONSE for the very warming scenario the check claims to cover.

NOTE: this is the same class as the parent JF-419 but for the SONG index. If subtask "single choke point" lands a generic mechanism, prefer reusing it over a new per-handler check.
