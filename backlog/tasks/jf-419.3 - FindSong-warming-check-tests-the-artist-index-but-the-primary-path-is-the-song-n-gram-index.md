## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Code-review finding (2026-08-31, high effort) on the JF-419 implementation. FindSongIntentHandler.cs:155.

DEFECT: FindSong's warming check tests the ARTIST index, but FindSong's primary path is the song n-gram index (SongNgramIndexService) whose independent IsReady is never checked. After a restart the artist index can be ready in ~2s while the song index (all Audio items) is still building: the gate passes, stages 1-2 are skipped by the inline `_songNgramIndex is { IsReady: true }` checks (lines 499/513), the request falls to the stage-3 Jellyfin search API, and the response can exceed Alexa's ~8s window. INVALID_RESPONSE for the very warming scenario the check claims to cover.

NOTE: this is the same class as the parent JF-419 but for the SONG index. If subtask "single choke point" lands a generic mechanism, prefer reusing it over a new per-handler check.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
JF-419.3: the warming gates are per-index with a give-up path, and both index services share one hardened lifecycle. Closes the JF-419 family.

WHAT CHANGED (commit 0e14aec, 25 files, +895/-532)
- DebouncedLibraryIndexService (new base class): the near-verbatim lifecycle copies of the two index services collapse into one shape (refresh lock, 5s debounce, failed-load retry, dispose ordering with volatile flag + in-lock re-checks, sticky readiness, LibraryManager, ResolveTopParentId). The song index gains JF-419.1 self-recovery and the dispose-race fix for free.
- Give-up path (review round 1): after 10 consecutive failed loads an index DISABLES itself; the warming gates treat a disabled index as absent so callers degrade to their bounded DB paths instead of an endless warming Tell (the review-proven regression where a persistently failing full-catalog load would have bricked song search). A later successful refresh (library change) re-enables. Shutdown cancellation no longer arms the retry timer; Release tolerates concurrent Dispose; debounce/retry share one hardened ArmOneShot.
- Per-path gates (review round 1 corrected the first cut): title-only FindSong/PlaySong gate on the SONG index; musician-scoped PlaySong gates on the ARTIST index (it never touches the song index; also restores refuse-before-announcement); AddToQueue/PlayNext gate on the song index (unbounded Audio SearchTerm scan) plus a conditional artist gate. Layer-2 choke point inside SongNgramIndexService.Search/SearchPhonetic (warming throws; disabled returns empty) so no future caller can silently treat a cold index as "no results". Pipeline log names the cold index.
- SongNgramIndexService indexes List<BaseItem> directly (SongEntry.TitleTokens was dead weight); SkillWarmingUpException.IndexName; WaitUntilAsync extracted to TestHelpers.
