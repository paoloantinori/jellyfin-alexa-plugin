## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Why

The static NLU tools of JF-954 reason about the EFFECTIVE model: the committed interaction model with each catalog-backed slot type's seed replaced by what catalog sync really uploads for the user's library. JF-954.1 ships a name-level snapshot producer that reads item names from the Jellyfin API in Python. That producer is an approximation: it does not reproduce the plugin's phonetic synonyms per locale, partial-name synonyms for artists and movies, seed merging (Album, Artist, Audiobook and Movie seeds are merged, Series seeds are not), the song-title preparation filters, the 140-character truncation, de-duplication by canonical name, or the value cap. Re-implementing those rules in Python would create a second copy that drifts. The deterministic answer is to ask the plugin itself to emit the payloads through the SAME code path the sync uses, without uploading anything. Read parent JF-954 first. This is the only JF-954 subtask that changes C# code, so the project's default Definition of Done (dotnet build, dotnet test, no new warnings, /simplify, /code-review) applies in full.

## Contract

The output is the snapshot format defined by JF-954.1 (`scripts/nlu_static/effective_model.py`, `load_snapshot`):
```json
{"schema": 1, "producer": "plugin", "locales": {"es-ES": {"SeriesName": [{"value": "Adolescencia", "synonyms": ["..."]}]}}}
```
Type keys are the slot type names from `CatalogSlotTypes.CatalogSlotTypeNames` (JellyfinArtist, AlbumName, SeriesName, AudiobookTitle, MovieTitle, SongTitle). Entries appear in the order the payload would be uploaded. A locale appears only when the sync would process it for that user (respect `PluginConfiguration.CatalogSyncLocales` and the ar-SA exclusion); a type appears only when the sync would upload it for that user (for example the song catalog only when the user's song sync is enabled).

## What to build

1. A read-only export on the plugin: `GET Plugins/AlexaSkill/Diagnostics/CatalogSnapshot?userId=<guid>[&locale=<locale>]` (put it in the existing `Controller/DiagnosticsController.cs` if its route and authorization fit, otherwise a new controller). Authorization: `[Authorize(Policy = "RequiresElevation")]`, the same attribute every `SimulatorController` action uses. An unauthenticated or non-admin request gets 401/403 and no data.
2. The export must call the SAME payload-building code as the real sync, not a copy. In `Alexa/Catalog/LibrarySyncService.cs` the per-type flow is: fetch items, for songs `SongTitlePreparation.Prepare(...)`, then `CatalogPayload.FromItems(catalogType, itemTuples, synonymGenerator, locale)`, then seed enrichment (`CatalogSeedEnrichment`, `MergeSeeds`), then `payload.TruncateTo(EffectiveMaxCatalogValues, staticAppendedCount)`. Extract that "build the final payload for (user, type, locale)" sequence into one method that both the sync and the export call, so the two cannot diverge. Keep the sync's behaviour byte-identical: the existing catalog tests must pass unchanged.
3. The export performs NO SMAPI call, creates no catalog version, registers nothing in the single-fetch payload cache served by `CatalogController`, and writes no configuration. It is a pure read of the library plus computation.
4. The response contains only slot values and synonyms. It must not contain tokens, API keys, skill ids, catalog ids, user names or item ids.
5. Python side: add `--from-plugin` to the `snapshot` subcommand of `scripts/nlu_static/cli.py`. It calls the endpoint with the `ApiKey=<key>` query parameter (capital A and K; Jellyfin 12 rejects `X-Emby-Token` and lowercase `api_key`), requires `--user-id`, validates the response with `load_snapshot` and writes it. The HTTP call stays behind the same injectable function JF-954.1 introduced so the unit test uses a fake.

## Guidance

- Before writing code, read `LibrarySyncService.cs` around the lines that call `CatalogPayload.FromItems` and `TruncateTo`, and `CatalogSeedEnrichment.cs`, and write in the task plan which statements move into the shared method. The refactor is the risky part; the endpoint is thin.
- Large libraries: the song catalog can hold about 10000 values per locale and several locales share identical payloads. Build each (type, locale) once; if two locales produce identical payloads it is fine to emit both. Enforce a request timeout through the existing cancellation token and do not block a thread pool thread with sync-over-async.
- Use `System.Text.Json` with the project's existing options; do not add a serializer.
- Tests (C#, in `Jellyfin.Plugin.AlexaSkill.Tests`): the shared builder returns for a fixed item list exactly what the sync path produced before the refactor (golden comparison on values and synonyms for at least Artist in it-IT and Series in es-ES); the export for a user with song sync disabled contains no SongTitle key; ar-SA never appears; the action carries the `RequiresElevation` policy (reflection test, same style as other attribute tests in the suite if present); the response JSON has no property other than `schema`, `producer`, `locales`, type names, `value`, `synonyms`.
- NEVER use `dotnet test --no-build` after code changes (project rule).
- Do not deploy to the live Jellyfin as part of this task. Verification on the running server is a maintainer step.
- Update `docs/nlu-static-analysis.md`: the two snapshot producers, when the name-level one is enough (fixture vocabulary membership) and when the authoritative one is needed (anything involving synonyms or the value cap).

## Out of scope

Changing what the sync uploads (for example merging Series seeds), any SMAPI interaction, any UI in `config.html`, deploying the plugin.
