## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Code-review finding (2026-08-31, high effort) on the JF-420 gate. PlayArtistSongsIntentHandler.cs:430.

DEFECT: the JF-420 gate fires on EXACT multi-word matches. FuzzyMatcher.cs:363 PartialRatio's containment shortcut is bidirectional, so any artist whose longer name embeds the query scores 90 (>= the 80 alternative threshold) while the JF-381 +10-char band kept it out of tier 1. With 'Pink Floyd' and 'The Pink Floyd Tribute Band' in the library, the exact request 'suona pink floyd' returns only Pink Floyd from tier 1 (Count==1), the gate finds the tribute band at score 90, the margin check (90-90=0 < 20) routes to the disambiguation prompt, where pre-JF-420 code auto-played the exact match.

LIVE EVIDENCE (2026-08-31): the live library gained 'Soul Coughing & Roni Size'; the exact query 'Soul Coughing' now prompts 'Ho trovato piu artisti: 1. Soul Coughing, 2. Soul Coughing & Roni Size' instead of auto-playing. Simulator test test_exact_artist_name_still_works is RED because of this. Reproduce via: POST $JELLYFIN_URL/Plugins/AlexaSkill/Simulator/Intent with musician 'Soul Coughing'.

FIX SHAPE: an exact (case-insensitive, whitespace-normalized) equality match between query and a tier-1 candidate should bypass the containment-comparison gate (the gate's purpose is resolving CONTAINMENT matches, and equality is the degenerate case where the penalized score equals the genuine one).
